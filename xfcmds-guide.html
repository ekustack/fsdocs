xfcmds and .xfcmd guide

Check packages, enable them with one prompt, and automate the IDE with plain sentence scripts

Open IDE IDE guide

What it is

xfcmds is the package and automation layer of the FSCSS IDE. It has four parts:

  • Package commands in the terminal: libs, libck, libon, liboff, yes, no.
  • The xfcmd command to run scripts by hand.
  • .xfcmd scripts: short, readable sentences that drive the IDE (create files, add snippets, compile, show panels).
  • The registry xfcmds/cmd.json in the FSCSS GitHub repo, which maps packages and commands to scripts.

Quick start

  1. Open the terminal with Ctrl+`.
  2. Type libs to list components.
  3. Type libck st-core. The IDE loads the package, checks it and prints a report.
  4. When it asks Enable st-core? Type yes or no., type yes.
  5. The package script runs: helper snippets are added and a demo file opens and compiles.
> libck st-core
Checking st-core...
st-core@2  by fscss-ttr  (MIT)
  import    @import((*) from st-core@v2)
Checks:
  [ok]   needs fscss ^1.1.24, compiler is 1.2.6
  [ok]   all 9 helpers found in modules
8 passed, 0 warnings, 0 failed
Status: not enabled. On enable it creates demos/st-core-demo.fscss; adds snippets; compiles.
Enable st-core? Type yes or no.
> yes

Afterwards, type a helper name such as st-root in the editor to insert its snippet.

Usage: terminal commands

CommandWhat it does

libs <query>Search name, description, author and keywords.

libs refreshReload the registry from GitHub, ignoring the 30 minute cache.

libon <name>Enable a package without the prompt. Fails if checks failed.
libon <name> forceEnable even when checks failed, or run the enable script again.
liboff <name>Disable a package: runs its disable script (if any), removes its snippets, forgets it. Files it created are kept.

no / nCancel the pending prompt.
xfcmd listShow registry commands, package hooks and .xfcmd files in your workspace.
xfcmd <name>Run a workspace file or a registry command. Same as xfcmd run <name>.
xfcmd check <name>Parse a script and show problems without running it.
xfcmd eval <sentence>Run a single sentence, for example xfcmd eval say "hi".
xfcmd refreshReload cmd.json from GitHub.

Names you can use with libck and libon:

  • A registry name: st-core. A version suffix is ignored for lookup, so st-core@v2 works too.
  • A GitHub shorthand: Koolkidkonrad/siri-wave.fscss.
  • A full URL: https://github.com/fscss-ttr/st-core.fscss. This works for packages that are not in libs.json.
  • A compiler built-in such as. The IDE tells you it is built in and there is nothing to download.

The prompt waits for 2 minutes. Running another libck replaces it. If you answer after it expired you get Nothing to confirm.

What libck checks

The report starts with package info (name, version, author, license, repo, issues link, import line, directive, helpers with their arguments, keywords). Then each check is marked [ok], [warn] or [fail].

CheckResult when it goes wrong
name, version, descriptionwarn
extension should be "fscss"warn
fscss_version against your compiler versionwarn if not satisfied or missing. Supports ^, ~, >=, <=, >, <, exact and ||.
directive such as st-* matches every helper prefixwarn
file.modules or file.remote presentfail
Each module file downloads (size and time are shown)fail on HTTP error or network error
Every listed helper is defined (@define name) or called in the module sourcewarn, with the missing names
blocked_methods are not used by the moduleswarn
The enable script parses cleanlyfail per bad sentence, with the line number

Modules are fetched from the repo root on main, then master. Paths such as ./st-core@v2.fscss are resolved against that root.

Warnings do not block enabling. Only failures do, and libon <name> force overrides those.

The .xfcmd language

A script is plain text. One sentence per line, run top to bottom. Lines that start with # or // are comments. Verbs are not case sensitive. Text goes in double quotes.

SentenceEffect
say "text" (also print, info)Print a line in the terminal.
warn "text" / error "text"Print at warning or error level.
toast "text" okShow a toast. The last word is optional: ok, warn or err.
add import <name>Insert @import((*) from name) at the top of the active FSCSS file (or the entry file). Skipped if already imported.
create file <path> with:
...lines...
end		Create a file from the lines between the sentence and a line that says end. Indentation is removed.
create file <path> with "text"Create a file from one quoted string. Use \n for new lines.
open file <path>Open a file in the editor.
set entry <path>Make a file the entry file.
compile / compile all / previewCompile the active file (or entry), every FSCSS file, or compile and show the preview.
show <view>Show files, components, snippets, tools, terminal, problems, css or preview.
add snippet <key> "<title>" as "<body>"Add an editor snippet. The key is what you type to trigger it.
add snippets for helpersAdd one snippet per helper listed in the package (package scripts only).
run command "<terminal command>"Run an allowed terminal command (see Control).
wait <n> msPause, up to 3000 ms.

Variables

Put a name in braces and it is filled in when the script runs.

VariableValue
{name} {version} {author} {description} {license} {repo}From the package.json of the package being enabled.
{import}The import name, from the main module file name (st-core@v2.fscss gives st-core@v2).
{helpers}Helper names, comma separated.
{fscss}The fscss_version range.
{file}The last file created or kept by create file.

Only the names above are replaced. Anything else in braces is left alone, so normal FSCSS like .card{ ... } inside a create file block is safe. In scripts you run yourself (not package scripts) the package variables are empty and only {file} is useful.

Quotes, escapes and blocks

  • Inside quotes, \n is a new line, \t a tab, \" a quote and \\ a backslash.
  • A sentence may end with a period right after the closing quote: say "Done".
  • Lines inside a create file ... with: block are not parsed, so # and // in your FSCSS are kept. The block ends at the first line that says end.
  • If the file already exists it is kept, not overwritten, and {file} points to it. Spaces in names become dashes and a name without an extension gets .fscss.
  • Snippet bodies use editor snippet syntax: ${1:name} for tab stops and $0 for the final cursor. To write a literal FSCSS variable such as $primary in a body, write \\$primary.

Examples

st-core.xfcmd (runs on libon st-core)

# st-core.xfcmd
say "Setting up {name}@{version} by {author}"
say "Helpers: {helpers}"
add snippets for helpers
create file demos/{name}-demo.fscss with:
  /* {name} demo, generated by xfcmd */
  @import((*) from {import})

  body{
    margin: 0;
    padding: 24px;
    font-family: system-ui, sans-serif;
  }
end
open file {file}
compile
show terminal
say "Done. Type a helper name such as st-root in the editor to insert it."

Order matters: the file is created, then opened, then compiled. compile works on the active file, so open file comes first.

hello.xfcmd (runs with xfcmd hello)

say "Hello from xfcmd."
run command "ls"
toast "Hello from xfcmd" ok

What the helper snippets look like

Each helper becomes a snippet named after it. Arguments in the helper signature become tab stops:

Helper in package.jsonSnippet inserted
st-root@st-root() with the cursor inside
siri-wave(st:.siri-wave)@siri-wave(.siri-wave) with the default selected
siri-blob-variant(st, color)@siri-blob-variant(st, color) with both selectable

Snippets are saved with the package and come back after a reload. liboff removes them.

Custom scripts

You can write your own scripts in the workspace. They are normal files, so they are saved, exported in the ZIP and JSON backup, and can be shared.

  1. Create a file with the .xfcmd extension, for example starter.xfcmd.
  2. Write sentences in it.
  3. Test with xfcmd check starter.xfcmd. Fix any line it reports.
  4. Run with xfcmd run starter.xfcmd.
# starter.xfcmd
say "Creating a starter theme"
create file styles/theme.fscss with:
  $primary: #0BCEAE;
  $radius: 8px;

  .btn {
    bg: $primary!;
    rounded: $radius!;
    px: 16px;
    py: 8px;
  }
end
set entry {file}
open file {file}
add snippet card "Card block" as ".card{\n  padding: ${1:16px};\n  rounded: ${2:8px};\n}"
compile
show preview
say "Starter ready."
Snippets from your own scripts last until you reload the page. Only enabled packages save their snippets. To keep a snippet permanently, run the script again after a reload, or ship it in a package script.
Try one line first. xfcmd eval say "hi" runs a single sentence without making a file. Blocks like create file ... with: need a real script.

Attach a script to your own package

Add an xfcmd field to the package.json (at the top level, or under file), pointing to a script in your repo:

{
  "name": "my-lib",
  "xfcmd": "./xfcmds/enable.xfcmd"
}

// or, to also run something on liboff
{
  "xfcmd": {
    "enable": "./xfcmds/enable.xfcmd",
    "disable": "./xfcmds/disable.xfcmd"
  }
}

The string form is the enable script. A script you ship is shown in the libck report (source and number of sentences), and the prompt lists what it will do before you answer.

Control and safety

  • Order: sentences run top to bottom. There are no if or loops by design, so a script always does the same thing.
  • Parse first: the whole script is parsed before anything runs. If any sentence is unknown or a block has no end, nothing runs and you get the line numbers.
  • Stops on error: if a sentence fails at run time (for example open file on a missing file), the script stops at that line. During enable, snippets added so far are removed and the package is not marked enabled. Files already created stay.
  • Preview before you commit: libck summarizes what enabling will do (files it creates, snippets, compile, commands) before you type yes.
  • Limits: 200 sentences per script, 3000 ms per wait.
  • Scripts are not code: they are never evaluated as JavaScript. They can only do what the sentence table above allows.
  • Allowed commands: run command accepts only compile, run, all, preview, ls, open, new, libs, clear, theme, routes, deps and resolve. Anything else, such as rm or version, stops the script with "rm" is not allowed in scripts.
  • Sources: remote scripts are fetched from raw.githubusercontent.com only.
  • Re-enabling: libon <name> force runs the script again. Existing files are kept and snippets with the same key are replaced.
  • Disabling: liboff never deletes files. Delete demo files yourself if you do not want them.
  • Where state lives: enabled packages are stored in localStorage under fside:pkgs (version, repo, import name, helpers, snippets, files created). Reset workspace clears them.

Package authors: making a package that passes libck

{
  "name": "my-lib",
  "version": "1.0.0",
  "description": "What it does in one line",
  "extension": "fscss",
  "fscss_version": ">=1.2.0",
  "blocked_methods": [],
  "repository": "https://github.com/you/my-lib.fscss",
  "bugs": "https://github.com/you/my-lib.fscss/issues",
  "author": "you",
  "license": "MIT",
  "keywords": ["fscss", "ui"],
  "file": {
    "usage": {
      "directive": "my-*",
      "helpers": ["my-card", "my-grid(cols:3)", "my-badge(label, color)"]
    },
    "modules": ["my-lib.fscss"],
    "remote": "my-lib.fscss"
  }
}
FieldNotes
name, versionShown in libs and libck. version can be a string like "2".
extensionUse "fscss".
fscss_versionCompiler range you support. It is compared with the IDE compiler version.
repository, bugs, authorEach can be a string or an object ({"url": "..."}, {"name": "..."}).
file.usage.directivePrefix pattern such as my-*. Every helper should start with it.
file.usage.helpersHelper names. Add arguments in the signature to get good snippets: name(a, b:default).
file.modules / file.remotePaths relative to the repo root. The file name of remote (without extension) becomes the import name.
blocked_methodsMethods your modules must not use. libck warns if they appear.
xfcmdOptional enable and disable scripts (see Custom scripts).

Checklist for a clean report:

  • The repo has package.json on main or master.
  • Every path in file.modules exists.
  • Every helper in file.usage.helpers is defined with @define in a module.
  • fscss_version covers the current compiler.
  • Add the repo URL to libs.json so it shows up in libs and the Components panel.

Run libck owner/repo from the IDE to test before you publish. It works for repos that are not in the registry yet.

The registry: xfcmds/cmd.json

The IDE reads xfcmds/cmd.json from the FSCSS GitHub repo. Scripts sit in the same folder. Add a package hook or a new command by editing this file and adding the .xfcmd file next to it.

FSCSS/
  xfcmds/
    cmd.json
    st-core.xfcmd
    hello.xfcmd
{
  "xfcmds": 1,
  "about": "IDE command scripts for FSCSS packages.",
  "packages": {
    "st-core": {
      "enable": "st-core.xfcmd",
      "disable": "st-core-off.xfcmd",
      "about": "Adds st-* helper snippets and a stats demo file"
    }
  },
  "commands": {
    "hello": {
      "script": "hello.xfcmd",
      "about": "Prints a greeting and lists your files"
    }
  }
}
  • packages: scripts that run when a package is enabled (enable) or disabled (disable, optional). The key is the package name from its package.json.
  • commands: standalone scripts anyone can run with xfcmd <name>.
  • Lookup order for enable: the package's own xfcmd field, then packages in this registry, then a built-in default (a message, helper snippets and the import line to use).
  • Fallback: if the registry cannot be fetched, the IDE uses a built-in copy for st-core and hello. xfcmd list tells you which one is active.

After you push changes, run xfcmd refresh in the IDE to reload the registry.

Troubleshooting

MessageMeaning and fix
No component named "x"Not in libs.json. Use owner/repo or the full GitHub URL, or run libs refresh.
No package.json found on main or masterWrong repo, private repo, or the file is on another branch.
module ...: HTTP 404A path in file.modules or file.remote does not exist. Paths start at the repo root.
helpers not found in modulesA listed helper has no @define. Fix the name or remove it from the list. This is only a warning.
needs fscss ^x but the compiler is yChange the compiler with version x.y.z or in Settings, or update the package range.
Unknown sentence: ...The line does not match any sentence. Check the verb and that text is in double quotes.
create file block is missing "end"Add a line that says end after the block.
"x" is not allowed in scriptsrun command only allows the commands listed under Control.
xfcmd line N: no such fileThe path in open file or set entry does not exist yet. Create it first, and check {file} if you used it.
Nothing to confirm.No prompt is pending, or it expired after 2 minutes. Run libck again.
xfcmd list says built-in fallbackThe GitHub xfcmds/cmd.json was not found. Check the path and branch, then xfcmd refresh.
Import fails after enablingCheck the import line in the libck report. Import names come from the module file name, for example st-core@v2.
