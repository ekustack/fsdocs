FSCSS API Reference

Public surface for FSCSS from v1.2.0 — two clean entry points, full backward compatibility with every 1.1.x method.

What changed in 1.2.0

Previous versions exposed scattered internal files (/e/exec.js, /exec.js, /xfscss.js, etc.). v1.2.0 consolidates everything into two public entry points:

  • runtime.js / runtime.min.js — drop-in browser script that auto-scans and runs
  • esm.js — pure ES module that never auto-runs (you call the API yourself)

The npm package and CLI remain completely unchanged. Every method that existed in 1.1.x still works.

Entry Points

runtime.js — Auto-run (Browser)

Use this for plain HTML pages. It automatically finds <link type="fscss"> and <style> elements, processes them, and injects the result.

HTML 
<link type="fscss" href="/style.fscss">
<script src="https://cdn.jsdelivr.net/npm/fscss@1.2.0/runtime.min.js" async></script>

Or the non-minified build:

HTML 
<script src="https://cdn.jsdelivr.net/npm/fscss@1.2.0/runtime.js" async></script>

Behavior:

  • Auto-boots on load (calls main() internally)
  • Fetches every [type*="fscss"] link
  • Processes all <style> elements and inline style attributes
  • Exposes the full xfscss object on the global scope so you can still call methods manually if needed

esm.js — Manual control (Modules)

Use this when you want full control: build tools, FSCSS-to-CSS converters, custom pipelines, or when you do not want the page to auto-process.

JavaScript 
import xfscss from "https://cdn.jsdelivr.net/npm/fscss@1.2.0/esm.js";

// Nothing happens until you call it
await xfscss.reboot();   // or xfscss.assign()
// or
const css = await xfscss.process(myFscssString);

Behavior:

  • Never auto-runs
  • Does not touch any loader element
  • Does not scan the DOM unless you explicitly call run(), assign() or reboot()
  • Ideal for offline compilation tools, Node-like environments (via bundlers), or selective processing

When to use which?

Use case Recommended
Quick HTML prototype / demo page runtime.js
Need to process only specific strings esm.js + process()
Build tool / FSCSS → CSS converter esm.js
Want auto-scan + still call API later runtime.js (global xfscss)
Production (recommended) CLI / npm package (compile ahead of time)

The xfscss Object

Both builds expose the same API surface:

JavaScript 
xfscss = {
  run:     fscssRunner,   // process all <style> elements
  inline:  fscssInline,   // strip selectors → declarations only
  process: fscssProcess,  // full FSCSS → CSS pipeline
  assign:  fscssAssign,   // full bootstrap (fetch + process + inline)
  exec:    fscssExec,     // inject text or URL and process
  reboot:  fscssReboot    // alias of assign
}

All methods that existed in 1.1.x continue to work exactly the same way.

xfscss.run()

Process every <style> element currently in the document

Scans document.querySelectorAll('style'), runs the full FSCSS pipeline on each, and replaces the content with the compiled CSS.

JavaScript 
await xfscss.run();

Notes

  • Does not fetch external <link type="fscss"> files (use assign / reboot for that).
  • Safe to call multiple times.
  • Errors are caught and logged to the console.

xfscss.process(css)

Full FSCSS → CSS transformation pipeline

Takes a string of FSCSS and returns a Promise that resolves to pure CSS.

JavaScript 
const pureCss = await xfscss.process(`
  $primary: #2563eb;
  .btn {
    background: $primary;
    padding: 12px 24px;
  }
`);

console.log(pureCss);
// .btn {
//   background: #2563eb;
//   padding: 12px 24px;
// }

This is the core engine. It runs (in order, unless blocked):

  1. Import selectors / from / full import
  2. VFC
  3. Pattern matching
  4. Store (before)
  5. External (before)
  6. Variables
  7. Functions / Fun objects
  8. Length / Count
  9. @define
  10. Arrays
  11. Events
  12. Random
  13. Copy / transform values
  14. Store (after)
  15. Numeric processing
  16. External (after)
  17. Transform group
  18. Debug

You can selectively disable stages with exec.obj.block(...) (see below).

xfscss.inline(css)

Strip selectors — keep only declarations

Useful when you want to apply processed FSCSS directly as an inline style attribute.

JavaScript 
const declarations = xfscss.inline(`
  .btn {
    background: #2563eb;
    color: white;
    padding: 12px 24px;
  }
`);
// → "background: #2563eb; color: white; padding: 12px 24px;"

element.setAttribute("style", declarations);

xfscss.assign() / xfscss.reboot()

Full bootstrap — the complete page processor

assign and reboot are aliases of the same function.

JavaScript 
await xfscss.reboot();   // preferred name in docs
// or
await xfscss.assign();

What it does (in order):

  1. Finds every [type*="fscss"] link and fetches them concurrently
  2. Injects the raw content into new <style> elements
  3. Runs processStyles() (the same pipeline as run())
  4. Processes every element that has a style attribute (using process + inline)

runtime.js calls this automatically on load.
esm.js never calls it — you must invoke it yourself when you are ready.

xfscss.exec({ type, content, onError, onSuccess })

Inject and process CSS/FSCSS on demand

Flexible helper for both inline text and remote URLs.

JavaScript 
// From a string
xfscss.exec({
  type: "text",          // or "auto", "fscss", "text/css", ...
  content: `
    $color: #e11d48;
    .alert { color: $color; }
  `,
  onSuccess: (styleEl) => console.log("Injected", styleEl),
  onError: (msg) => console.error(msg)
});

// From a URL
xfscss.exec({
  type: "fromUrl",       // or "URL", "link", "external"
  content: "https://example.com/theme.fscss",
  onSuccess: (styleEl) => { /* ... */ },
  onError: (msg) => { /* ... */ }
});

Supported type values

  • Text mode: "text", "auto", "text/fscss", "text/css", "text/xfscss", "fscss"
  • URL mode: "fromUrl", "URL", "fromURL", "link", "external"

After injection the full bootstrap (main / reboot) is triggered so the new styles are processed immediately.

exec.obj.block(...) — Selective pipeline control

Disable individual processing stages

Inside any FSCSS source you can write directives that skip specific stages of the pipeline. This is useful for debugging or when you only need a subset of features.

FSCSS 
/* Skip the entire pipeline */
exec.obj.block(all);

/* Or skip individual stages */
exec.obj.block(f import);
exec.obj.block(pattern);
exec.obj.block(store);
exec.obj.block(fun);
exec.obj.block(define);
exec.obj.block(arr);
exec.obj.block(event);
exec.obj.block(random);
exec.obj.block(copy);
exec.obj.block(num);
exec.obj.block(debug);
/* ... and many more */

All exec.obj.block(...) markers are stripped from the final CSS output.

Compatibility Guarantee

Every public method and feature that worked in FSCSS 1.1.x continues to work in 1.2.0.

  • npm package & CLI — unchanged
  • All @define, @event, pattern(), arrays, stores, etc. — unchanged
  • Only the browser entry-point files were consolidated

You can safely upgrade. Old CDN URLs will keep working for a transition period, but new projects should use the two entry points documented above.
