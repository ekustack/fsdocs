Styling Nested divs with One Loop

Generate div, div div, div div div… with a single @arr + rpt() pattern. No more hand-written selector chains.

This guide combines arrays & loops with rpt() from the core docs. Requires FSCSS v1.1.x+ (examples use the 1.2.0 runtime).

The problem

Writing nested selectors by hand is painful and error-prone:

CSS — the hard way
div { background: orange; }
div div { background: purple; }
div div div { background: indigo; }
/* …and it gets worse the deeper you go */

You have a simple nested structure:

HTML
<div>1
  <div>2
    <div>3</div>
  </div>
</div>

You want each level to have a different background (and maybe padding, radius, etc.) without maintaining a growing list of selectors.

The one-loop solution

HTML + FSCSS
<script src="https://cdn.jsdelivr.net/npm/fscss@1.2.1/runtime.min.js" async></script>

<style>
@arr colors[orange, purple, indigo]
@arr levels[count(@arr.colors!.length, 1)]          /* → 1, 2, 3 */

rpt(@arr.levels[], "div ") {      /* builds "div ", "div div ", "div div div " */
  background: @arr.colors[@arr.levels[]];
  padding: 10px;
  border-radius: 10px;
  color: #fff;
  margin: 8px;
}
</style>

That’s the whole pattern: one levels array, one colors array, one rpt() in selector position.

What gets generated

Compiled CSS
div {
  background: orange;
  padding: 10px;
  border-radius: 10px;
  color: #fff;
  margin: 8px;
}

div div {
  background: purple;
  padding: 10px;
  border-radius: 10px;
  color: #fff;
  margin: 8px;
}

div div div {
  background: indigo;
  padding: 10px;
  border-radius: 10px;
  color: #fff;
  margin: 8px;
}

How it works

  1. @arr levels[count(3, 1)] creates the numbers 1, 2, 3. count(n, start) needs a literal number (see building modules for the limit).
    From version 1.2.1 count can also count length of an array: count(@arr.name!.length)
  2. rpt(@arr.levels[], "div ") sits in selector position. For each level it repeats the string "div " that many times: "div ", "div div ", "div div div ".
  3. Inside the block, @arr.colors[@arr.levels[]] picks the color for the current index (arrays are 1-indexed in this usage).
  4. FSCSS expands the whole rule once per array item — one clean loop, pure CSS after compile.

The same selector-position + block rule that drives array loops in general is what makes the expansion reliable here.

Easy variations

Change depth

Update count() or sync to the array length (version 1.2.1+) and the colors array together so they stay in sync:

FSCSS
@arr colors[tomato, coral, salmon, crimson]
@arr levels[count(4, 1)]

rpt(@arr.levels[], "div ") {
  background: @arr.colors[@arr.levels[]];
  padding: 10px;
  border-radius: 10px;
}

Child combinator instead of descendant

FSCSS
rpt(@arr.levels[], "div > ") {
  /* generates: div >, div > div >, div > div > div > */
  background: @arr.colors[@arr.levels[]];
}

Different values per level

Reference the level index for anything — font-size, opacity, animation-delay, etc.:

FSCSS
@arr colors[orange, purple, indigo]
@arr sizes[1rem, 0.9rem, 0.8rem]
@arr levels[count(3, 1)]

rpt(@arr.levels[], "div ") {
  background: @arr.colors[@arr.levels[]];
  font-size: @arr.sizes[@arr.levels[]];
  padding: 10px;
  border-radius: 10px;
  color: #fff;
}

Other tags or class chains

FSCSS
@arr levels[count(3, 1)]

rpt(@arr.levels[], ".card ") {
  /* .card , .card .card , .card .card .card */
  border: 1px solid #334155;
  padding: 12px;
}

Why this feels good

  • Zero repetitive typing — depth and styles stay in one place
  • Depth and colors stay in sync — change count() and the parallel arrays together
  • Still pure CSS after compilation — no runtime cost for the nested rules
  • Works with browser runtime or CLI — same source either way

Hand-writing nested selectors used to be a small but annoying chore. With FSCSS arrays + rpt(), it becomes a reusable one-liner pattern.
